## Features

- The interface is now built on Native Shell on every platform, replacing the
  previous toolkit. The screens look the same and do the same things; the
  rendering, the animation and the text input underneath are new, and the
  browser page, the desktop window and the phone now come from one codebase
  rather than three.
- A browser can drive Kitty Pro. `Kitty-Pro-web-*.tar.gz` holds a self-hosted
  control surface: a process that runs the core and the page that talks to it,
  served from the same port. Open `http://127.0.0.1:7897/`. A browser cannot
  raise a system network interface, so the web page is a control surface, not a
  VPN client.
- Android is a full release channel: the APK now carries the core itself, so
  the phone routes its own traffic over `tun0`. It is signed with the same key
  as every previous APK, so it installs over an existing one.
- DNS rules match the way routing rules do. A dedicated DNS rule can now be an
  exact domain, a suffix or a keyword instead of only a suffix. Existing rules
  and existing synced snapshots keep meaning what they always meant.
- The interface is available in 简体中文 and English, chosen on the settings
  page.

## Bug Fixes

- Connecting actually routed traffic. On a packaged build, starting the
  privileged interface opened a second window instead of answering the first,
  so it timed out; the shipped macOS, Windows and Linux builds all inherited
  this.
- A 32-bit ARM phone was told there was no build for it, whatever was
  published, and so could never update.
- The desktop app no longer reports version 0.1.0. The About panel, the
  updater, and a bundle's own version field (what Finder shows on macOS) all
  read the release tag now.
- A self-hosted web server no longer offers itself a desktop installer as an
  update.
- On Android the page header sat under the clock and signal icons, and the
  import sheet could hide behind the keyboard.
- The settings page lost its rail, every button has one height across the app,
  and the window no longer draws a title bar over the content.

## Known limitations

- A packaged desktop build does not clean up when it is killed abruptly. Quit
  it from its own interface: the core stops and routes come down; what an
  abrupt exit can leave behind is a system proxy pointing at a process that has
  gone.
- iOS still has no build.

## 新功能

- 界面全面改用 Native Shell 实现，替换了原来的工具链。界面外观与操作不变，底层的
  渲染、动画和文本输入是新的；浏览器页面、桌面窗口和手机端现在出自同一套代码，而不
  是三套。
- 浏览器可以操控 Kitty Pro。`Kitty-Pro-web-*.tar.gz` 是自托管的控制台：一个运行内核
  的进程，加上与它同端口提供的页面，打开 `http://127.0.0.1:7897/` 即可。浏览器无法
  创建系统网络接口，所以网页是控制台，不是 VPN 客户端。
- Android 成为正式渠道：APK 自带内核，手机可以自己跑 `tun0` 转发。签名与之前的 APK
  一致，可以直接覆盖安装。
- 专用 DNS 规则现在可以像分流规则一样匹配：精确域名、后缀或关键词，不再只有后缀一
  种。已有规则和已有云端快照的含义不变。
- 界面支持简体中文与 English，在设置页切换。

## 修复

- 点击连接之后真的会转发流量。打包版启动特权接口时会再开一个窗口而不回应第一个，
  因此总是超时；macOS、Windows、Linux 的发行包都有这个问题。
- 32 位 ARM 手机过去无论发布什么都提示"没有适配你的版本"，因此永远无法更新。
- 桌面端不再显示版本 0.1.0。关于页、检查更新、以及安装包自身的版本号（macOS 上
  Finder 显示的那个）现在都读取发布标签。
- 自托管的 Web 服务端不再把桌面安装包当成自己的更新推送给用户。
- Android 上页面标题被状态栏遮挡，导入弹层会被键盘挡住。
- 设置页去掉了侧边导航栏，全应用按钮高度统一，窗口不再用标题栏压住内容。

## 已知限制

- 打包的桌面版被强制结束时不会做退出清理。请从界面内退出：内核会停止、路由会撤除；
  被强制结束时可能残留一个指向已退出内核的系统代理设置。
- iOS 仍然没有构建。
