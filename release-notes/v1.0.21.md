## Features

- **Updates install themselves.** Settings → Check for updates now downloads
  the matching desktop archive, verifies its size and SHA-256, replaces the app
  and restarts into the new version. 1.0.19 predates the updater config, so
  moving to 1.0.21 is a one-time manual install; from 1.0.21 on, the app can
  update itself.
- **Launch at login uses the system's own login item.** NSH 0.6's native
  launch-at-login replaces the launch agent and registry value this app used to
  write. An existing registration is migrated on start: the new item is enabled
  first, and the old one is removed only after the system reports the new one
  on, so upgrading never turns autostart off.

## Bug Fixes

- **The web control surface recovers from a server restart.** The server mints
  a new session token on every start, so a page left open across a restart kept
  sending the old cookie and every `/api/*` call answered HTTP 403 — shown as
  "the server replied with something unreadable". The page now renews the
  session cookie and retries the call once, with no manual reload. If it is
  still refused, the message names the real cause — an expired session or a
  reverse proxy that rewrites `Host` — and the `KITTY_PRO_ALLOWED_HOSTS` fix.

## 新功能

- **应用内更新可以直接安装。** 设置里的「检查更新」会下载对应的桌面安装包，
  校验大小和 SHA-256，然后由内置更新器替换应用并重启进入新版本。1.0.19
  本身没有 updater 配置，所以这次需要手动安装一次 1.0.21；从 1.0.21 起就能
  在应用内升级。
- **开机启动改用系统自己的登录项。** NSH 0.6 原生的 launch-at-login 取代了
  应用以前自己写的 launch agent 和注册表项。升级时会迁移已有的开机启动设置：
  先打开新的登录项，确认系统接受后再移除旧项，不会因为升级把开机启动关掉。

## 修复

- **Web 控制面在服务重启后自动恢复。** 服务进程每次启动都会换会话 token，
  之前还开着的页面会一直带着旧 cookie，所有 `/api/*` 请求都返回 HTTP 403，
  界面显示成「服务端返回了无法理解的内容」。现在页面会自动重新获取会话 cookie
  并重试一次，不需要手动刷新。如果重试后仍被拒绝，提示会说明是会话过期，还是
  反向代理改写了 Host，并给出 `KITTY_PRO_ALLOWED_HOSTS` 的修法。
